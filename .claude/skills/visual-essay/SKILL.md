# Visual essay

A **visual essay** is a written essay published so that its prose and its
figures carry equal weight: the text runs verbatim as the spine, and between
its paragraphs sit figures built from the run's own data, several of them
driven by the reader's scroll or hands. This file is about **process**: how the
figures are specified, fed, built, verified and shipped. It says nothing
binding about how the page looks. The look lives in the **current skin**
(`references/conventions.md` and `references/scaffold.html`) and is expected to
be overhauled; everything below should survive that unchanged.

The skill builds on the **scrolldeck** skill's tooling (its static-SVG QA loop
is reused as is) without inheriting its slide structure.

## Find the reference essay (do this first, every time)

```bash
ls -t $(grep -l 'data-scrolly=' *.html) | head -3
```

`data-scrolly=` is the format's marker: every visual essay's scroll-scrubbed
figures carry it, and nothing else on the site does. **Keep that attribute
name through any restyling.** Read the newest result end to end before
building — its figure code, how its data is embedded, how its captures were
made — and prefer its current practice over anything here that contradicts
it. When you finish an essay, push what generalizes back into this file (if it
is process) or into the skin files (if it is look).

## The two rules you cannot break

1. **Every static SVG, hand-authored or script-generated, passes the scrolldeck
   Overlap-QA loop** (`../scrolldeck/references/overlap-qa.md` with its
   `isolate_and_render.js` and `splice_back.js`): one editing agent per SVG,
   in parallel, four-class rubric, splice back, confirm the renders yourself.
2. **Every script-built figure passes the review-agent pass**
   (`references/review-qa.md`). Canvas sequences, charts built at runtime and
   widgets have no block to isolate, so you capture their *states* with the
   harness and one review-only agent per figure judges them against the rubric
   and the figure's stated intent; you fix the page from its report. On the
   first essay this returned about fifty findings over six figures, three of
   them bugs a reader would have hit on the first scroll. It is mandatory for
   the same reason the SVG loop is: you authored the coordinates, so you
   cannot see them.

## Figure types (by how they are built and verified, not how they look)

- **Static figure** — an inline SVG. Hand-authored, or *generated by a script
  from the data* whenever geometry encodes data (positions on a recovered
  circle, arrows whose length is a weight, a chart of a recorded series).
  Verified by the Overlap-QA loop.
- **Live figure** — an SVG the page's JS builds from the embedded data, often
  with hover, toggles or a lens. Verified by the review pass.
- **Scrolly** — a pinned stage that is a pure function of scroll progress
  `p ∈ [0,1]`, with step captions whose thresholds match the stage's phases.
  Verified by the review pass at several `p`.
- **Canvas sequence** — a scrolly whose stage is a `<canvas>` redrawn at every
  `p` (`references/canvas-sequences.md`). Verified by the review pass.
- **Widget** — sliders, drag, toggles, a "random" button; recomputes from the
  embedded data on every input. Verified by the review pass in two or more
  states.
- Every script-built figure also ships a **no-JS fallback**: an image of its
  final state captured from the page itself.

## Principles

1. **Prose verbatim; the essay's "Visual" notes are the figure spec.** The
   source essay's figure blocks give each caption and a "Visual" paragraph.
   Build what the paragraph says, in the essay's words, before improving it.
   Port the text as written; the scope is the main text unless told otherwise,
   and cross-references to anything left out are dropped.
2. **Every drawn number comes from the run, through one script.** Locate the
   artifacts (results JSON, tables of record, banked arrays, a remote volume
   if that is where they live); write a `compute.py` that derives every
   figure's data *and asserts the essay's own claims against it*; embed the
   result in the page (`references/data-pipeline.md`). Never hand-type a value
   a script can derive; never let a figure disagree with the prose.
3. **Colour is assigned by role.** One accent for the essay's recovered
   structure and chrome, one fixed categorical set for its recurring objects,
   used identically in every figure. Which hues those are is the skin's
   business; that they are consistent is not.
4. **Scrubbed, not animated.** A stage never moves on its own: `draw(p)` is
   idempotent and the reader's scroll is the clock. Reduced-motion still
   scrubs; it only drops reveals and parallax.
5. **Every figure stands without JavaScript and at phone width.** Fallback
   images and a list rendering of the step captions for no-JS; no horizontal
   overflow at 400 px (display math, pinned stages, floating panels are the
   usual offenders).
6. **State on screen must agree with itself.** A counter, a readout, a caption
   and a marker visible at the same `p` must tell one story; reviewers check
   this and so should you.

## Build workflow

1. **Read** the essay source and the reference essay. For each figure block
   decide the type and write its **intent in one paragraph**: every element
   and what it means. That paragraph is used twice — as the figure's
   `aria-label`/alt text and as the QA agents' brief — so write it well.
2. **Get the data and write `compute.py`**: load artifacts, derive each
   figure's arrays, assert each stated claim, write a compact data file
   (rounded floats, seeded samples of large scatters, per-bin envelopes).
3. **Decide the colour roles** (accent, categorical set) and register the
   matching arrowhead markers.
4. **Copy the current skin's scaffold**, fill in metadata, port the prose.
5. **Build the figures.** Data-driven static SVGs come from a generator script
   (geometry computed, labels placed by rule, never eyeballed). Live figures
   and widgets build from the embedded data. Scrollies register
   `registerScrolly(id, draw)`. Canvas sequences follow
   `references/canvas-sequences.md`.
6. **Assemble** (`references/assemble.py`): generated SVGs and the data file
   fill the template's `{{PLACEHOLDERS}}` once. From then on the HTML in the
   repo is the source of truth; QA fixes go there.
7. **Render everything** with the harness (`references/render.mjs` on the
   `qa_copy.py` localized copy): the full page with reveals forced, each
   scrolly at four or five values of `p`, each widget in two states, each
   hover and toggle. Read every capture yourself before any agent does.
8. **QA pass 1** — static SVGs through the Overlap-QA loop; splice; confirm.
9. **QA pass 2** — script-built figures through the review pass; fix every
   finding; re-render; re-read; re-review any figure whose fix was structural.
10. **Fallbacks** — capture each script-built figure's final state (viewport
    mode, element clip) into `resources/`, wrap it in `<noscript>`; build and
    read the no-JS variant and the phone-width render.
11. **Share card** — the skin's template, rendered through the harness
    (a plain `--screenshot` hangs on CDN fonts).
12. **Wire in** — archive entry and sitemap per `references/conventions.md`.
    Final sweep: no `{{` left, every `resources/` reference exists, tags
    balance, no `PAGE ERROR` in any harness log, scroll width equals viewport
    width at 400 px, every claim in `compute.py`'s report matches the prose.

## Scrolly mechanics (invariant; the values live in the scaffold)

- Progress is `p = (scrollY − rootTop) / (root.offsetHeight − stage.offsetHeight)`,
  clamped to [0,1], measured on load and resize, updated on scroll through one
  `requestAnimationFrame`. The stage is pinned; step spacers give the scroll
  its length and are hidden under JS; the caption strip shows the step whose
  threshold `data-at` ≤ `p`.
- Thresholds must sit on the stage's own phase boundaries, and whatever the
  stage prints (a counter, an epoch, a label) must agree with the caption at
  every `p` in that step.
- Controls that live on the stage are positioned absolutely and must have a
  narrow-screen rule (scale or relocate); check them at phone width.
- Capturing a pinned stage requires the harness's viewport mode; a clipped or
  beyond-viewport capture un-pins it.

## The render harness

`references/render.mjs` (Node ≥ 22, no dependencies) drives headless Chrome
over the DevTools protocol from a `jobs.json` (`references/jobs.example.json`).
Three capture modes: the full page, an element clip, and viewport mode for
anything pinned. `prep` runs arbitrary JS first — the example's `__sp(id, p)`
scrubs a scrolly, hovers are dispatched `mouseenter` events, sliders are
`value=` plus an `input` event — and a `prep` that returns something other
than `1` prints it, which makes it a probe (overflow width, element counts,
built-figure child counts). Any `PAGE ERROR` line is a failure.

Always render the `qa_copy.py` copy (CDN stylesheet and MathJax pointed at
local files). The harness already waits for `readyState` *interactive*, forces
instant scrolling, waits for fonts and MathJax, and kills Chrome on exit; do
not reintroduce one-shot `--screenshot` renders for anything but a single
static file, and even then expect them to hang on remote fonts.
